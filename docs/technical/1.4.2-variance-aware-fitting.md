# §1.4.2 Variance-aware fitting

The Jedrzejewski (1987) algorithm and the Python predecessors that
implement it fit harmonics by ordinary least squares with uniform
weights. Modern wide-field surveys — HSC-SSP, DECaLS / BASS / MzLS,
DES, eventually LSST — deliver a per-pixel inverse-variance map
alongside the science image, but the classical algorithm has no
mechanism for consuming it. The information is therefore thrown
away, with two consequences: outlier pixels (cosmic rays, hot
pixels, masked-bad pixels that survived the bad-pixel map) carry
the same weight in the harmonic fit as good pixels; and parameter
uncertainties are estimated from the *scatter on the ellipse* —
which conflates per-pixel photon noise with the intrinsic
azimuthal scatter from galaxy structure (spiral arms, dust lanes,
bars, faint companions) — rather than from the photon noise the
variance map already encodes.

ISOSTER closes this gap by accepting a `variance_map` argument to
`fit_image` and routing all harmonic fits through a weighted
least-squares (WLS) path when one is supplied. The path is
algorithmically separate from the OLS path: every WLS branch is
gated on a variance map having actually been supplied, so when
`variance_map = None` not one weighted operation executes and the
output is bit-for-bit what the same code produced before the WLS path
existed. When a variance map is supplied, every
harmonic fit on every isophote — geometry fit, ISOFIT extended fit,
post-hoc higher-order fit, forced-extraction fit, multi-band joint
fit — switches to WLS uniformly. There is no half-WLS configuration
in which some harmonic fits use weights and others do not.

## §1.4.2.1 OLS vs WLS at the algorithm level

The OLS normal equations for the design matrix $\mathbf{A}$ and the
sampled intensities $\mathbf{y}$ are

$$
\mathbf{A}^\mathsf{T}\mathbf{A}\,\mathbf{x} = \mathbf{A}^\mathsf{T}\mathbf{y},
$$

with parameter covariance

$$
\mathrm{Cov}(\hat{\mathbf{x}})_\mathrm{OLS}
= (\mathbf{A}^\mathsf{T}\mathbf{A})^{-1}\,\hat\sigma_\mathrm{res}^2,
$$

where $\hat\sigma_\mathrm{res}^2$ is the *residual variance*
estimated empirically from the fit residuals,

$$
\hat\sigma_\mathrm{res}^2
= \frac{1}{N - P}\sum_{i=1}^{N}
  \left(y_i - [\mathbf{A}\hat{\mathbf{x}}]_i\right)^2,
$$

with $P$ the number of parameters the fit actually carried. The
residual-variance rescaling is necessary precisely because OLS has no
external scale for the noise — the matrix
$(\mathbf{A}^\mathsf{T}\mathbf{A})^{-1}$ alone has the wrong units,
and the only available scale is what the residuals themselves
provide.

Two details of that rescaling matter enough to state. First, it is
computed **once per isophote**, from the exact fitted model — the
five-parameter model, or the wider ISOFIT model when higher orders
were fit inside the loop — evaluated at the angular coordinate the
coefficients were fitted in. That single value scales both the
geometry block and the higher-order harmonic errors, so one fit
yields one error scale; the optional background floor
$\hat\sigma_\mathrm{res}^2 \ge \sigma_\mathrm{bg}^2$ is applied at the
same point, once, rather than on individual consumers. Evaluating a
*truncated* model to rescale a wider fit would charge genuine fitted
structure to the noise, and would leave two parts of the same
isophote reporting errors on different scales. Second, when the fit
is exactly determined — as many samples as parameters, which is
precisely where ISOFIT switches on — the model passes through every
point and the data carry no information about the noise level. The
residual variance is then reported as zero, meaning "not measurable",
which is a different statement from "not supplied".

The WLS normal equations replace $\mathbf{A}^\mathsf{T}\mathbf{A}$
and $\mathbf{A}^\mathsf{T}\mathbf{y}$ with their weighted analogues,
using the diagonal weight matrix $\mathbf{W} = \mathrm{diag}(1 /
\sigma_i^2)$ where $\sigma_i^2$ is the per-pixel variance at the
$i$-th sample point along the ellipse:

$$
\mathbf{A}^\mathsf{T}\mathbf{W}\mathbf{A}\,\mathbf{x}
= \mathbf{A}^\mathsf{T}\mathbf{W}\mathbf{y},
$$

with parameter covariance

$$
\mathrm{Cov}(\hat{\mathbf{x}})_\mathrm{WLS}
= (\mathbf{A}^\mathsf{T}\mathbf{W}\mathbf{A})^{-1}.
$$

The WLS covariance requires no residual-variance rescaling. The
inverse-variance weights have units of $1/\mathrm{intensity}^2$, so
the dimensional argument that forced the OLS rescaling does not
apply here: $(\mathbf{A}^\mathsf{T}\mathbf{W}\mathbf{A})^{-1}$
already has units of $\mathrm{intensity}^2$ on the parameter axes
that are themselves in intensity units.

Calling it *exact* would overstate the case, and the conditions
under which it is a calibrated uncertainty are worth naming, since
both are routinely violated by survey data. The first is that the
variance map correctly describes the per-pixel noise; correlated
noise from coaddition, underestimated sky variance, or a zeropoint
calibration error all propagate straight through into
over-confident error bars, and §1.4.2.4 returns to this. The
second is subtler and is a property of ISOSTER's own sampling
rather than of the input: the samples along a ring are produced by
bilinear interpolation from the underlying pixel grid, so
neighbouring samples share source pixels and are *not*
statistically independent, while $\mathbf{W}$ is diagonal and the
covariance expression assumes they are. At the default sampling
density of roughly one sample per pixel of perimeter the
correlation is modest, but it grows as the sampling density rises
relative to the pixel scale, and it biases the reported
uncertainties low. The WLS covariance is therefore best described
as free of the OLS estimator's structural bias, and calibrated to
the extent that the variance map is calibrated and the ring samples
can be treated as independent.

The two practical consequences of switching from OLS to WLS are
worth naming explicitly. *Outlier down-weighting*: a single
hot-pixel sample with $\sigma_i^2 = 10^{6}$ relative to the
$\sigma^2 \sim 1$ of the neighbouring sky-noise pixels carries a
weight $10^{-6}$ times smaller than its neighbours in the harmonic
fit. The classical OLS path would weight that pixel equally and let
a single outlier swing the dominant harmonic amplitude;
WLS effectively masks it without the caller having to identify the
pixel ahead of time. *Error-bar decoupling*: the two estimators
answer different questions, and it is worth being careful about
what does and does not follow from that.

Under the textbook model the residual-scatter estimator is not
deficient at all. If the samples are independent with a common
variance, then $\hat\sigma_\mathrm{res}^2$ is an unbiased estimate
of that variance and the OLS covariance is a correct — indeed
optimal — description of the photon noise. In that case OLS and WLS
have the *same* expected covariance, and neither is systematically
larger. Any claim that the scatter estimator is "bounded below by
the photon noise it fails to capture" is simply false in this
regime, and an earlier version of this section made it.

What separates the two in practice is the failure of the textbook
model's two assumptions. When the variance is *not* common across
the ring, the weighted estimator uses information the unweighted one
discards, and the two diverge in a direction that depends on where
the low-variance samples sit relative to the structure being fitted
— it is not one-signed. When the residual contains real azimuthal
structure the five-parameter model does not absorb — spiral arms,
dust lanes, orders $n \ge 3$ — the scatter estimator counts that
structure as noise and is inflated relative to pure photon noise;
this is the regime where OLS error bars are *larger*, not smaller.
And $\hat\sigma_\mathrm{res}^2$ carries its own sampling error of
order $\sqrt{2/(N-P)}$, so on a single ring it can land either side
of the truth.

How far apart the two estimators fall on real survey data, and in
which direction, is what the demonstration of §1.4.2.5 is for. That
galaxy has not yet been selected and the comparison has not been
run, so no ratio is quoted here; an earlier version of this section
gave one, but it described an experiment that had not been
performed. The durable argument for WLS does not depend on the
answer: it is that WLS returns error bars traceable to a stated
noise model, which can be checked against the survey's own variance
map, rather than to a residual scatter that mixes photon noise with
whatever the model failed to fit.

## §1.4.2.2 Per-pixel gradient error propagation

The error bar on the mean intensity $I_0$ propagates
straightforwardly from the variance map. In the free fit, $I_0$ is
the intercept of the harmonic fit, so its variance is the
intercept element of the WLS parameter covariance,

$$
\mathrm{Var}(I_0)_\mathrm{WLS}
= \left[(\mathbf{A}^\mathsf{T}\mathbf{W}\mathbf{A})^{-1}\right]_{0,0},
$$

and ISOSTER reports $\sqrt{\mathrm{Var}(I_0)}$ as `intens_err` in
the WLS path. Two qualifications. When the fit covariance is
unavailable, the fallback is the variance of an inverse-variance-
weighted mean, $\left(\sum_i \sigma_i^{-2}\right)^{-1}$ — the right
form there, because template-based forced photometry reports a plain
weighted mean rather than a fitted intercept. And under the `'median'`
integrator the reported intensity is not the fitted intercept at all,
so `intens_err` comes from the median's own variance instead; see the
paragraph on the deliberate mean/median asymmetry below. The OLS
analogue is $\mathrm{rms} / \sqrt{N}$ (with the $\sqrt{\pi/2}$ median
penalty where applicable), which inherits the
photon-noise-vs-azimuthal-scatter conflation discussed above.

The more interesting propagation is the *radial gradient* error,
because that is the quantity that drives the convergence criterion
and the gradient-SNR damping (§1.1, §1.3) and because its OLS
estimate is structurally biased in a way the intensity-error
estimate is not. The radial gradient $dI / da$ is computed in
ISOSTER from two samples at offset SMAs: a central sample at the
current $a$ and an offset sample at $a + \Delta a$ (or
$a (1 + \Delta a)$ for multiplicative SMA stepping). The two
samples produce two mean intensities $\bar I_c$ and $\bar I_g$
(plain unweighted means, or medians under the `'median'`
integrator), and the gradient is

$$
\widehat{dI/da}
= \frac{\bar I_g - \bar I_c}{\Delta r},
$$

with $\Delta r$ equal to the radial separation between the two
samples (either $\Delta a$ in linear-stepping mode or $a \cdot
\Delta a$ in multiplicative-stepping mode). Assuming the two
samples are statistically independent — they sample different
elliptical paths through the image and the per-pixel photon noise
is uncorrelated between distinct pixels — the variance of the
gradient is

$$
\mathrm{Var}\!\left(\widehat{dI/da}\right)
= \frac{\mathrm{Var}(\bar I_c) + \mathrm{Var}(\bar I_g)}{(\Delta r)^2},
$$

and the WLS gradient error is

$$
\sigma_{dI/da}^\mathrm{WLS}
= \frac{\sqrt{\mathrm{Var}(\bar I_c) + \mathrm{Var}(\bar I_g)}}{\Delta r}.
$$

The per-ring variance on the right-hand side must be the variance of
*the estimator that was actually used to locate the ring*, and this is
the point at which a plausible-looking shortcut goes wrong. The two
ring locations are an unweighted mean or an unweighted median; the
variance of an inverse-variance-*weighted* mean,
$\left(\sum_i \sigma_i^{-2}\right)^{-1}$, belongs to a different
estimator and understates the uncertainty of an unweighted mean
whenever the variances differ around the ring. ISOSTER therefore
computes location and variance together in one helper
(`_ring_statistic_and_variance` in `isoster/_shared.py`), so the
reported gradient and its error can never come from two different
estimators on two different sample sets. For a ring of $N$ surviving
samples with per-sample variances $\sigma_i^2$ the two forms are

$$
\mathrm{Var}(\bar I)_\mathrm{mean}
= \frac{1}{N^2}\sum_{i=1}^{N} \sigma_i^2,
\qquad
\mathrm{Var}(\bar I)_\mathrm{median}
= \frac{\pi N}{2 \left(\sum_{i=1}^{N} \sigma_i^{-1}\right)^{2}}.
$$

The first is the ordinary variance of a mean of independent,
non-identically-distributed measurements. The second is a
normal-theory asymptotic result which, for uniform variance
$\sigma_i^2 = \sigma^2$, reduces to $\pi\sigma^2 / (2N)$ — the mean's
$\sigma^2/N$ inflated by the familiar factor $\pi/2 \approx 1.571$
that makes the median the less efficient estimator under Gaussian
noise. The median form is an approximation rather than an exact
result: its derivation assumes independent, identically distributed
Gaussian samples, whereas a real ring carries genuine azimuthal
structure and neighbouring samples are correlated through the
bilinear interpolation that produced them. Monte Carlo tests agree
with the closed forms to about $0.08\%$ for uniform per-sample
variance and $1.4\%$ for spatially varying variance — accurate enough
to trust as an error estimate, but not exact in the way a
first-principles derivation on independent samples would be.

Either way the expression is *pure photon noise*: the only quantities
on the right-hand side are the per-pixel variances at the two sampled
ellipses and the geometric separation $\Delta r$. Galaxy-structure
scatter does not appear, because the harmonic-fit residuals are not
used.

**A deliberate asymmetry between the reported intensity and the
gradient.** Under WLS with the default mean integrator, the ring
intensity ISOSTER reports is *not* the unweighted mean that enters the
gradient: it is the inverse-variance-weighted intercept of the
harmonic fit, whose error is the exact covariance element of
equation §1.4.2.2 above. The gradient, by contrast, always uses the
unweighted ring statistic on both rings. The two quantities are
computed for different purposes and the difference is intentional.
The intensity is a per-isophote photometric measurement, where
down-weighting noisier pixels is exactly what one wants; the gradient
is a *comparison* between two rings, where using the same simple
estimator on both sides is what keeps the comparison honest. Under
the median integrator the reported intensity is an unweighted median
even when a variance map is supplied, so `intens_err` comes from the
median's own variance above rather than from the weighted intercept.
Rescaling the weighted intercept's error by $\sqrt{\pi/2}$ to
manufacture a median error is correct only for uniform variance:
once the noise varies with angle, the intercept of a five-parameter
fit becomes correlated with the sine and cosine terms and its variance
is no longer the median's by any constant factor. Measured across
several spatial variance patterns, the rescaled value ranged from
$0.75\times$ to $3.21\times$ the correct median error, so the
shortcut can understate as well as overstate the uncertainty.

The OLS analogue, by contrast, replaces both $\mathrm{Var}(\bar
I_c)$ and $\mathrm{Var}(\bar I_g)$ with scatter-based estimates of
the form $s_c^2 / N_c$ and $s_g^2 / N_g$, where $s_c^2$ and $s_g^2$
are the plain sample variances of the intensities around the two
ellipses (with the same $\pi/2$ penalty applied under the median
integrator). This substitution looks innocent — both quantities
have units of $\mathrm{intensity}^2$ — but it conflates two
different sources of variance. The scatter $s_c^2$ at a single
ellipse contains both the per-pixel photon noise *and* the intrinsic
azimuthal variation of the galaxy structure at that radius. The
latter is precisely what the harmonic decomposition is trying to
*measure*. Subtracting the fitted harmonic contribution would help,
and would be the natural refinement, but even the residual after the
five-parameter fit still carries azimuthal structure from orders
$n \ge 3$ that the geometry fit does not absorb. The scatter-based
gradient error should therefore be read as an *upper bound* on the
photon noise rather than an estimate of it, and the size of the
excess depends on the morphological complexity of the galaxy in a
way that is difficult to characterize a priori.

The bias matters because $\sigma_{dI/da}$ does not merely decorate
the output: it feeds the convergence criterion through the
gradient-SNR damping (§1.3.2), where a gradient SNR below 3 reduces
the geometry-update damping factor to prevent overfitting the noise
floor, and it feeds the `maxgerr` gate that decides when the outward
sweep has run out of usable gradient. It also decides, through the
relative error $|\sigma_{dI/da} / (dI/da)|$, whether ISOSTER pays for
a second, wider-baseline gradient sample at $a + 2\Delta a$ before
accepting the value. Overestimating $\sigma_{dI/da}$ — the typical
scatter-estimator failure mode on a galaxy with prominent spiral
structure — therefore damps the geometry update *more aggressively
than the data warrants*, spends sampling effort on a second baseline
that was not needed, and can stop the outward sweep early on a
gradient that was in fact well measured. WLS removes the bias by
replacing the scatter estimate with the variance-map propagation, and
the gradient-SNR criterion then reflects the actual photon noise. When
either ring's variance is not finite, ISOSTER reports the gradient
error as *unavailable* rather than as an enormous number, so a
degenerate ring cannot masquerade as a merely uncertain one.

A practical observation. The WLS gradient error formula above is
algebraically equivalent to the standard photon-noise propagation
for the difference of two means; nothing in it is novel. What is
novel is that the classical isophote-fit literature *predates* the
routine availability of per-pixel inverse-variance maps, and
implementations written in that era reasonably estimated gradient
errors from residual scatter because that was the only available
estimate. The WLS path in ISOSTER simply uses the better estimate
when the user supplies the data for it.

## §1.4.2.3 Input handling and safeguards

The `variance_map` argument is an array of the same shape as the
science image (a `ValueError` is raised at the top of `fit_image`
otherwise) carrying the per-pixel variance $\sigma_i^2$. The
following sanitization rules are applied in order:

- **Shape and dtype check.** The variance map is coerced to a
  float-64 NumPy array; integer or float-32 inputs are converted
  with a copy. The caller's array is never mutated.

- **Invalid entries are marked, then dropped.** A per-pixel variance
  carries usable information only if it is finite and strictly
  positive. Every entry that is not — `NaN`, $\pm\infty$, zero, or
  negative — is marked `NaN` internally, and the sampler then
  *excludes the affected samples outright*, exactly the way it
  already excludes masked pixels. One `RuntimeWarning` is emitted
  per category (non-finite, non-positive) reporting how many entries
  were affected. The marking is performed on a copy; the caller's
  `variance_map` remains as supplied.

- **Copy-on-write.** The internal sanitized array is held in a
  buffer separate from the caller's `variance_map`. A caller can
  pass the same `variance_map` to multiple `fit_image` calls
  (typical of survey pipelines that fit the same galaxy at
  multiple bands or with multiple `IsosterConfig` variants)
  without worrying about cumulative side effects.

The governing principle is that **a ring statistic and its
uncertainty must always describe the identical set of samples**.
Dropping is the only policy that satisfies it. Two earlier
mechanisms, both now retired, substituted a placeholder value
instead: non-finite entries became a large sentinel ($10^{30}$),
intended to give the pixel a negligible weight, and non-positive
entries were clamped to a small positive value ($10^{-30}$),
intended to bound the weight instead of dividing by zero. Both
kept the flagged pixel *inside* the ring while distorting how much
it counted. The sentinel is finite and strictly positive, so the
validity rule kept it despite the intent; the clamp was worse, giving
a single unusable pixel a near-infinite weight that could collapse
an inverse-variance-weighted error by fourteen orders of magnitude.
Neither failure announced itself in the output, which is the reason
to state the policy explicitly rather than leave it to a docstring.

**Checking the sampled value alone is not sufficient.** Variances are
read with bilinear interpolation, which blends each sample from the
four surrounding image pixels. A `NaN` or an infinity propagates
through that blend on its own and always reaches the validity check.
Zero and negative entries do not: an isolated zero-variance pixel
averaged with three positive neighbours yields a positive
interpolated variance that the check accepts, leaving an unusable
sample in the ring with an understated variance. Measured on a flat
test map with a true variance of $4.0$, one zero-variance source
pixel produced an interpolated variance of $1.95$, and one negative
pixel produced $1.44$. ISOSTER therefore also validates the four
source pixels feeding each sample. Because `fit_image` has already
marked every unusable entry before any sampling happens, the source
check is redundant on that path and is skipped there; it costs at
most about $0.11\,\mathrm{ms}$ per ring on a direct call to the
lower-level fitting functions, which are public and may legitimately
be handed a raw, unvalidated map. Instrumenting a 62-isophote fit of
a $1133 \times 1133$ image confirms the check runs *zero* times
inside `fit_image`, so the normal pipeline carries no extra cost.

The canonical inverse-variance-to-variance conversion is therefore:

```python
variance_map = np.where(invvar > 0, 1.0 / invvar, np.nan)
```

This states the `invvar = 0` masked-out convention explicitly at the
call site, which is clearer than relying on ISOSTER's internal
marking, though the two give the same result. Callers who prefer to
be explicit about exclusion may equivalently fold those pixels into
the `mask` argument; ISOSTER treats the two routes identically.

The multi-band path (§1.4.5) applies the same rule to each band's
map. It differs in one structural detail: every multi-band entry point
that accepts a raw variance map routes through a single resolver, so
the arrays handed to the sampler are always pre-marked and the
source-pixel check has nothing left to catch. There is consequently no
multi-band equivalent of the "already prepared" flag, because there is
no unprepared path.

## §1.4.2.4 Caveats and composability

Three caveats apply to the WLS path:

**Variance maps do not replace masking.** The drop policy of
§1.4.2.3 applies only to variances that are *invalid* — non-finite or
non-positive. A pixel that is merely very noisy is valid data: with
$\sigma_i^2 = 10^{6}$ it still contributes a weight of $10^{-6}$ to
the harmonic fit, not zero. For a single bad pixel on an
isophote with $N \sim 1000$ samples this is negligible; for
pathological cases where a large fraction of the ellipse is
covered by high-variance pixels (a defect that spans an arc of the
ellipse, a bright companion's diffraction spike crossing the
isophote) the residual weight can still bias the fit. The
recommended practice is to combine `variance_map` with a binary
`mask` array that excludes pixels the caller knows to be unusable;
WLS then operates on the remaining pixels with weights derived
from their physical photon noise.

**Variance maps inherit upstream systematics.** If the survey
inverse-variance map underestimates the true noise — typically the
case for coadded imaging where pixel-to-pixel noise is correlated
and the naive per-pixel variance does not reflect the effective
noise per resolution element — WLS produces over-confident error
bars on the harmonic-fit parameters and on the gradient. ISOSTER
cannot diagnose this from the variance map alone; the caller is
responsible for correcting the variance map upstream, typically
through a noise-rescaling factor estimated from blank-sky regions
or from a covariance-matrix model of the coaddition.

**Uniform-variance equivalence.** What makes WLS and OLS coincide
on the *fitted values* is the variance being nearly uniform around
the ellipse — not the signal-to-noise being high. The two are
easily confused because they often occur together, but they are
independent conditions, and it is the first that matters: WLS
differs from OLS only through the relative weights it assigns to
samples, so a ring whose per-pixel variances are all equal produces
the same normal equations either way, at any signal level. Where the
variances *do* vary around the ring — a coadd depth gradient, a
dither-pattern seam, a masked region's soft edge — the weights are
non-uniform, and the fitted geometry, harmonic coefficients and
curve-of-growth differ between the two paths regardless of how
bright the galaxy is. In the uniform case the fitted values agree to
within LAPACK floating-point determinism and only the error bars
differ, WLS using the variance-map propagation and OLS the residual
scatter. Users who
do not have a variance map should not invent one to enable WLS
"just in case"; the OLS path produces correct geometry estimates
on its own, and a fabricated variance map only contaminates the
error bars.

The WLS path composes cleanly with every other ISOSTER feature.
All sampling modes (φ-uniform and ψ-uniform), all harmonic-fit
modes (post-hoc, `'in_loop'` ISOFIT, `'original'` ISOFIT), all
constraint flags (`fix_center`, `fix_pa`, `fix_eps`), the LSB
outskirt features (§1.4.3), the batch-robustness primitives
(§1.4.4), and the multi-band joint free fit (§1.4.5) all carry the
WLS weights through unchanged. (The multi-band case adds a wrinkle
worth naming here rather than leaving entirely to §1.4.5.2: the joint
solve composes the per-pixel inverse-variance weights with a per-band
factor derived from that band's radial gradient, so the *effective*
weight on the shared geometry is not $1/\sigma_i^2$ alone. The
per-pixel weights enter unchanged; what changes is what they are
multiplied by.) The composability is a property of
the implementation: the weight matrix enters as a single row-wise
prescaling of $\mathbf{A}$ before the normal equations are formed,
$\mathbf{A}_W = \mathbf{W}\mathbf{A}$, after which
$\mathbf{A}_W^\mathsf{T}\mathbf{A}$ and
$\mathbf{A}_W^\mathsf{T}\mathbf{y}$ are solved directly. (The OLS
branch instead calls NumPy's least-squares driver on the unweighted
$\mathbf{A}$; the two branches are deliberately separate so that the
OLS path is untouched by the existence of the WLS one, which is what
makes the byte-identity claim of §1.4.2.1 checkable rather than
merely asserted.) Every harmonic fit in the package — the
five-parameter geometry solve, the wider ISOFIT solves, the
higher-order post-hoc fits — goes through this same pair of
branches. Adding a new feature that affects the harmonic fit does
not require a parallel WLS implementation; it inherits the
weighted solve automatically.

## §1.4.2.5 Demonstration: LegacySurvey galaxy with inverse-variance map

To make the OLS / WLS difference visible we use a LegacySurvey
(DECaLS) galaxy from the SGA-2020 sample, drawn from the curated
demonstration subset in `sga_isoster/data/demo/` (an external
companion repository, not part of the ISOSTER source tree). The galaxy is a
moderately bright disk-dominated late-type system at intermediate
inclination, large enough that the outward fit pushes well into
the LSB regime where the OLS / WLS distinction becomes
quantitatively significant. The science image is the $r$-band
coadded frame in nanomaggies, and the variance map is constructed
from the LegacySurvey per-pixel inverse-variance ($\mathtt{invvar}$)
extension by

$$
\sigma^2(x, y) = \begin{cases}
1 / \mathtt{invvar}(x, y) & \mathtt{invvar} > 0,\\
\mathrm{NaN} & \mathtt{invvar} = 0,
\end{cases}
$$

following the canonical recipe of §1.4.2.3, so that pixels the
survey excluded from its own inverse-variance calculation are
excluded from the isophote fit as well rather than being assigned a
weight.

demanding: disk-truncation edges, intracluster light, stellar-halo
profiles — the two estimators are answering different questions, and
the figure's job is to show how far apart their answers fall on real
survey data and in which direction. As §1.4.2.1 sets out, that
direction is not determined a priori: the scatter estimator is
inflated where the model leaves real azimuthal structure in the
residual and can fall either side of the truth on any single ring.
Whichever way the envelopes separate, the argument for WLS is that
its envelope is traceable to a stated noise model that can be
checked independently.

The inner region is the intended control, and it is a control only
if a condition holds that we have not yet checked. The two solves
coincide when the weights are near-constant around a ring — a
*variance-uniformity* condition, not a signal-to-noise one. Whether
the LegacySurvey inverse-variance map satisfies it for the galaxy
eventually chosen is exactly the thing the figure should report,
either by stating the ring-uniformity criterion the object was
selected on or by showing the ring-variance profile alongside. If it
does not hold, the inner envelopes will separate too, and that would
be a finding rather than a failure of the figure.

The reproducibility recipe is:

```python
import numpy as np
from astropy.io import fits
from isoster import fit_image
from isoster.config import IsosterConfig

image = fits.getdata("galaxy-r.fits.fz")
invvar = fits.getdata("galaxy-invvar-r.fits.fz")
variance_map = np.where(invvar > 0, 1.0 / invvar, np.nan)

config = IsosterConfig(sma0=10.0, maxsma=200.0,
                       full_photometry=True)

# OLS baseline (no variance map)
results_ols = fit_image(image, mask=mask, config=config)

# WLS fit (same config, variance map supplied)
results_wls = fit_image(image, mask=mask, config=config,
                        variance_map=variance_map)
```

The two `results` dictionaries are two independent fits, and how far
they differ outside the `*_err` fields depends on the variance map.
Where the weights are nearly constant along each ellipse — the
uniform-variance condition of §1.4.2.4, not a high-$S/N$ condition —
the fitted geometry, the harmonic coefficients and the
curve-of-growth fields agree to within LAPACK floating-point
determinism. Where the map varies on the scale of a ring, the
weights change the solve itself and the fitted values move too. The
plotting recipe accordingly reads both dictionaries and draws
*each fit's own* $\mu(a)$ curve with its own envelope. Collapsing
them onto one shared central curve would silently assert the
uniform-variance case rather than displaying it.

A final practical point. The structural cost of WLS is small: the
weighted solve is the same size as the unweighted one, the weights
enter as a single elementwise row scaling, and the wider design
matrix that makes the ISOFIT path of §1.4.1 expensive has no
counterpart here. The one genuine addition is sampling the variance
map alongside the image on every ring, which is a second
`map_coordinates` call per sampling pass. We have not isolated the
resulting overhead in a controlled benchmark, so we quote no
number for it; the expectation from the operation count is that it
is small relative to a fit's total cost, and confirming that belongs
with the other timing measurements in the benchmark chapters. For
survey pipelines processing
thousands of galaxies with already-computed inverse-variance maps,
turning on WLS is the obvious default.
